## Packaged env-file execution — 2026-10-20

On macOS with Node 22.19.0 / npm 10.9.3, the previous bin shebang reproduced `node: alternate.env: not found` (exit 9) before the CLI could resolve the file against `--cwd`. The new package regression suite fails against that shebang and passes with the protected entry point. Type checking and the existing 49 tests also passed.

Node 22.19's [startup code](https://github.com/nodejs/node/blob/v22.19.0/src/node.cc#L865) reads env-file arguments before normal option parsing; its [env-file scanner](https://github.com/nodejs/node/blob/v22.19.0/src/node_dotenv.cc) stops at `--`. A boundary is needed at every Node launch: the installed bin shebang, direct local MCP command, and the outer npx command. `#!/usr/bin/env -S node --` supplies it for POSIX bins. npm 10.9.3's [cmd-shim 7 parser](https://github.com/npm/cmd-shim/blob/v7.0.0/lib/index.js) recognizes `env -S`, generating Windows Node commands with `--` rather than invoking Unix env.

`npm run test:package` builds and packs the package, installs its tarball into an isolated consumer with locked dependencies, and executes the installed bin and real offline npx. It checks default/relative/absolute/equals env-file paths from another directory, a conflicting caller file, process and URL precedence, empty keys, missing-file errors, and file preservation. Files containing `NODE_OPTIONS` must remain application data. Local and pinned npx MCP commands generated by actual setup complete SDK handshakes, list compact tools and read the bundled guide; setup also preserves unrelated settings and reruns unchanged.

The CI matrix now runs this suite on Ubuntu, macOS and Windows with Node 22 and 24, including CMD and PowerShell npm shims on Windows. Local macOS results do not establish Windows/Linux or native client UI results. A new published version still needs independent registry installation QA after review, merge and release.

## Existing-key installation recovery — 2026-10-20

The 0.1.4 candidate was verified on macOS with Node 24.19.0. Type checking, all 68 source tests, and the packed tarball suite passed (7 passed, 1 Windows-only test skipped locally).

- Uncertain exchange, invalid or incomplete responses, unknown HTTP errors and credential-save conflicts instruct callers to check `.env` first, preserve saved and reused keys, inspect the code and selected key in Steercards, and use a fresh code for the same usable key when needed. Only a newly issued key explicitly confirmed unused is eligible for manual cleanup.
- All six `AGENT_INSTALL_KEY_*` errors use static messages; server prose, tokens and installation codes are not printed. Each attempted exchange is submitted once, and unrelated `.env` data and external edits survive failures.

It checks the key-preserving error and next steps, one exchange, unchanged CRLF `.env` content, and no server prose or secrets on stdout/stderr. Installed CLI, generated local/npx STDIO server info, and HTTP client info match the package version.
- Package contents include compiled code, Skill and documentation; no `.env`, test fixtures, dependencies or Git metadata are packed. No production key or installation code was used.

Remote OS/Node CI, npm publication/provenance and independent public-registry installation QA remain separate checks. These fixture results do not establish native client UI or production exchange behavior.
